# Crawler Generator

ساخت کرالر خبر با React و TypeScript و Codex SDK محلی. تنها ورودی اجباری URL فهرست خبر است. خبر نمونه اختیاری است و در حالت عادی از فهرست استخراج‌شده انتخاب می‌شود.

## جریان ساخت

1. HTML اولیهٔ فهرست دریافت می‌شود؛ اگر شواهد خبری داشته باشد، Codex قواعد استخراج از HTML یا JSON داخل آن را می‌سازد.
2. استخراج واقعاً اجرا می‌شود. اگر HTML کافی نباشد یا دو تلاش نتیجهٔ معتبر ندهد، مرورگر مستقل باز می‌شود و برای پاسخ‌های XHR/fetch منتظر می‌ماند.
3. پاسخ‌های JSON و MessagePack خوانا به‌عنوان شواهد API بررسی می‌شوند. اگر دادهٔ API قابل خواندن نباشد، DOM یا دادهٔ ساخت‌یافتهٔ ایجادشده در مرورگر بررسی می‌شود. هیچ کوکی یا پروفایل مرورگر شخصی استفاده نمی‌شود.
4. یک خبر از فهرست انتخاب می‌شود و همین مسیر مستقل برای متن کامل آن طی می‌شود؛ روش فهرست و جزئیات الزاماً یکسان نیست.
5. قواعد استخراج به بستهٔ TypeScript مستقل تبدیل می‌شوند. فایل واقعی تولیدشده در فرایند جدا اجرا می‌شود، فهرست را دوباره دریافت می‌کند و متن یک خبر دیگر (در صورت وجود) را استخراج می‌کند.
6. فقط پس از استخراج حداقل یک لینک خبر و متن خبر حداقل ۱۲۰ نویسه، نسخهٔ جدید فعال می‌شود. در شکست، نسخهٔ قبلی حفظ می‌شود و علت در لاگ ثبت می‌شود.

Codex قواعد اختصاصی CSS selector، مسیر JSON و الگوی URL را مطابق قرارداد مشخص تولید می‌کند. برنامه از این قواعد کد TypeScript می‌سازد؛ کد آزاد و نامحدود مدل روی سرور اجرا نمی‌شود. اگر سایتی به تبدیل خارج از این قرارداد نیاز داشته باشد، تولید باید خطا بدهد، نه موفقیت ظاهری با خروجی خالی.

## راه‌اندازی

نیازمندی: Node.js 22 یا جدیدتر.

```powershell
npm install
npx playwright install chromium
npm run dev
```

رابط در `http://localhost:5173` است. `.env.example` را به `.env` کپی کنید. ورود Codex محلی باید برای کاربر سیستمِ اجراکنندهٔ سرور آماده باشد؛ نیازی به کپی‌کردن توکن ورود نیست.

```env
CODEX_MODEL=gpt-5.6-terra
CODEX_REASONING_EFFORT=medium
BROWSER_WAIT_MS=15000
GENERATION_TIMEOUT_MS=600000
LOG_DIR=logs
```

برای استفاده از نصب موجود مرورگر می‌توانید `PLAYWRIGHT_CHANNEL=msedge` یا `chrome` بگذارید. در هر دو حالت یک مرورگر headless با context تازه باز می‌شود. با خالی‌گذاشتن آن Chromium نصب‌شده توسط Playwright استفاده می‌شود. تغییر `.env` به راه‌اندازی مجدد سرور نیاز دارد.

PostgreSQL و Redis با `docker compose up -d` در دسترس‌اند؛ فعلاً اخبار در دیتابیس نوشته نمی‌شوند.

## اجرای مستقل

```powershell
npm run run:generated
# خواندن مجدد خبرها بدون فیلتر سابقه:
npm run run:all
# بررسی فقط فهرست و یک خبر، بدون تغییر سابقه:
npm run verify:generated
```

اجرای عادی تمام خبرهای دیده‌نشدهٔ فهرست را می‌خواند؛ محدودیت ۱۰ خبر وجود ندارد. برای دریافت تمام خبرهای فهرست حتی خبرهای قبلاً خوانده‌شده، `npm run run:all` را اجرا کنید. URL خبرهای موفق در `crawler-state-<hostname>.json` در پوشهٔ اجرای فرمان ذخیره می‌شود؛ `--state=path` مسیر را تغییر می‌دهد. برای جلوگیری از برخورد روی فایل سابقه، اجراهای هم‌زمان را با یک مسیر state مشترک انجام ندهید. `--all` سابقه را نه می‌خواند و نه تغییر می‌دهد. منظور از تمام اخبار، لینک‌های استخراج‌شده از فهرست فعلی است؛ آرشیو، صفحه‌بندی و اسکرول نامحدود خودکار انجام نمی‌شود.

هر اجرای کرالر خودکار یک فایل UTF-8 JSON در پوشهٔ `outputs` همان سایت می‌سازد و مسیر کامل را در لاگ و فیلد `outputFile` نشان می‌دهد. فایل شامل `listing` (تمام خبرهای فهرست با لینک و عنوان)، `items` (جزئیات استخراج‌شده)، `errors`، `discovered`، `skippedSeen` و `status` است. هر خبر علاوه بر `content` متنی، دارای `contentHtml` پاک‌سازی‌شده با لینک‌ها، تصاویر و ساختار HTML، `imageUrl`، آرایه‌های مستقل `categories` و `tags`، زمان ISO در `publishedAt` و `author` است. داده‌ای که واقعاً در سایت وجود نداشته باشد جعل نمی‌شود و مقدار خالی می‌گیرد. فایل پس از دریافت فهرست و هر خبر به‌روز می‌شود؛ `running` یعنی اجرا هنوز تمام نشده، `completed` یعنی موفق، `partial` یعنی برخی خبرها خطا داشته‌اند و `failed` یعنی خطای کلی رخ داده است. اجرای `--verify` هم فایل می‌سازد، اما فقط متن یک خبر را آزمایش می‌کند.

برای اجرای یک نسخهٔ مشخص و دریافت تمام فهرست:

```powershell
node --import dotenv/config --import tsx generated/sites/<site-name>/crawler.ts --all
# مسیر خروجی دلخواه (فایل باید جدید باشد):
node --import dotenv/config --import tsx generated/sites/<site-name>/crawler.ts --all --output=results/fars.json
```

خروجی‌های قبلی بازنویسی نمی‌شوند؛ مسیر دلخواهِ موجود با خطای `EEXIST` رد می‌شود. JSON نتیجه همچنان روی stdout و گزارش‌ها روی stderr هستند. اگر بعضی خبرها شکست بخورند، بقیه ذخیره می‌شوند و exit code برابر ۱ است؛ خبرهای ناموفق وارد سابقه نمی‌شوند. در اجرای عادی، `items: []` وقتی طبیعی است که همهٔ خبرهای قابل بررسی قبلاً خوانده شده باشند؛ `listing` همچنان تمام فهرست را نگه می‌دارد. دستورهای npm تنظیمات مرورگر را از `.env` پوشهٔ اجرای فرمان می‌خوانند.

خروجی‌های جدید با نام دامنه در `generated/sites/<site-name>/` قرار می‌گیرند؛ برای نمونه `farsnews-ir`. فایل `crawler.ts` این پوشه آخرین نسخهٔ موفق همان سایت را اجرا می‌کند و نسخه‌های آزمایش‌شده در زیرپوشهٔ `versions/<timestamp>/` باقی می‌مانند. فایل `generated/crawler.ts` نیز آخرین کرالر موفق میان همهٔ سایت‌ها را هدایت می‌کند. هر نسخه شامل `crawler.ts`، `runtime.ts`، `recipe.ts`، `recipe.json`، `package.json` و پس از قبولی `sample.json` است. برای انتقال، پوشهٔ نسخه را کپی کنید، `npm install` و در صورت نیاز `npx playwright install chromium` اجرا کنید، سپس `npm start`. این بسته به Codex یا پروژهٔ سازنده وابسته نیست.

## گزارش‌ها و تست‌ها

رابط، HTML/API/مرورگر، انتخاب خبر، اصلاح استخراج، آزمایش زنده و نتیجهٔ نمونه را نمایش می‌دهد. رویدادها در ترمینال و `logs/<requestId>.jsonl` ذخیره می‌شوند. اگر اجرای Codex طول بکشد، هر ۱۰ ثانیه پیام انتظار می‌آید. فایل لاگ فعلاً پاک‌سازی خودکار ندارد.

HTML، پرامپت، پاسخ خام مدل و اطلاعات ورود لاگ نمی‌شوند. پیام‌های خطا پالایش می‌شوند؛ پیش از اشتراک‌گذاری لاگ بازبینی کنید. بستن یا تازه‌کردن صفحه، اجرای متصل را لغو می‌کند؛ فایل‌های لاگ باقی می‌مانند.

API قبلی `POST /api/generate` حفظ شده است: `{ listingUrl, articleUrl? }`. هدر `Accept: application/x-ndjson` گزارش زنده و رویداد نهایی `result` یا `failure` برمی‌گرداند. بدون این هدر پاسخ نهایی JSON است. نمونهٔ استخراج و روش هر مرحله در نتیجه وجود دارد.

```powershell
npm run build
npm test
```

برای سایت‌های نیازمند ورود، CAPTCHA یا پاسخ‌های رمزگذاری‌شده، دورزدن محدودیت انجام نمی‌شود. پاسخ غیرقابل خواندن API فقط با دادهٔ قابل مشاهده در صفحه جایگزین می‌شود؛ در نبود دادهٔ معتبر، ساخت شکست می‌خورد. تغییر ساختار سایت ممکن است نیاز به تولید دوباره داشته باشد. قوانین سایت و مجوز کرال را رعایت کنید.
